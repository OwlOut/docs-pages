structure-pages-srr

🧠 SSR / NextJS / Capacitor, Pourquoi ça fonctionne ?​

Dans Next.js, on peux faire SSR via :

  • Pages Router (getServerSideProps, etc.)
  • App Router (fetch directement dans les composants server)

On peux isoler la logique métier (controller) dans un fichier réutilisable, et l’appeler côté serveur ou client selon le contexte.

🧱 Exemple avec SSR dans le Pages Router (/pages)​

✅ Structure​

pages/
└── events/
    ├── controller.ts        ← contient la logique de récupération
    ├── view.tsx             ← composant d'affichage
    └── index.tsx            ← page avec SSR

📁 controller.ts​

// pages/events/controller.ts

import axios from 'axios';

export async function fetchEventsFromAPI() {
  const res = await axios.get('https://api.example.com/events');
  return res.data;
}

📁 view.tsx​

// pages/events/view.tsx

interface EventsViewProps {
  events: any[];
}

export const EventsView = ({ events }: EventsViewProps) => (
  <ul>
    {events.map((event) => (
      <li key={event.id}>{event.title}</li>
    ))}
  </ul>
);

📁 index.tsx avec getServerSideProps​

// pages/events/index.tsx

import { GetServerSideProps } from 'next';
import { fetchEventsFromAPI } from './controller';
import { EventsView } from './view';

export const getServerSideProps: GetServerSideProps = async () => {
  const events = await fetchEventsFromAPI();

  return {
    props: {
      events,
    },
  };
};

export default function EventsPage({ events }: { events: any[] }) {
  return <EventsView events={events} />;
}

✅ Exemple dans le App Router (/app) avec async components​

// app/events/page.tsx

import { fetchEventsFromAPI } from './controller';
import { EventsView } from './view';

export default async function EventsPage() {
  const events = await fetchEventsFromAPI();
  return <EventsView events={events} />;
}

🧠 Astuce : sépare la logique statique/serveur et client​

Si tu as aussi besoin de gérer :

  • des états interactifs (filtrage dynamique)
  • des appels API client (recherche, ajout...)

Tu peux faire :

// controller.server.ts → appels SSR
// controller.client.ts → logique useEffect, useState

Et utiliser l’un ou l’autre selon le contexte (server ou client).

🟡 TL;DR​

Avec ce patternSSR compatible ?Commentaires
controller + view✅ OuiTrès clair et modulaire
Avec getServerSideProps✅ OuiAppelle le controller côté serveur
Dans App Router (app/)✅ OuiAvec async server components
SSR + client state✅ Avec structure propreSéparer server et client logic
